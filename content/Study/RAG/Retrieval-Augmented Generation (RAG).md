## 개요

파운데이션 모델은 과거 시점에 고정되어 있을 뿐만 아니라, 의도적으로 자연스럽고 다양한 응답을 생성하도록 설계되었습니다. 이 두 가지 특성은 모델이 자신감 있게 부정확하고 관련 없는 결과물을 내놓게 할 수 있습니다. 이러한 행동을 "환각(hallucination)"이라고 합니다.

이 글에서는 파운데이션 모델의 한계점을 살펴보고, 검색 증강 생성(Retrieval-Augmented Generation, RAG)이 이러한 한계를 어떻게 해결하여 채팅, 검색 및 에이전트 워크플로우에 기여할 수 있는지를 다룹니다.

## 파운데이션 모델의 한계

파운데이션 모델만으로 구축된 제품들은 뛰어나지만 다음과 같은 여러 한계점을 가집니다.

### 지식 단절 (Knowledge cutoffs)

파운데이션 모델에게 지난주 NBA 농구 경기 결과나 최신 아이폰 모델의 기능 사용법과 같은 최신 사건에 대해 질문하면, 오래되었거나 완전히 조작된 정보를 자신감 있게 제공할 수 있습니다. 모델은 대규모 데이터셋으로 학습되지만, 학습이 완료된 후 데이터는 특정 시점에 고정되기 때문에 '지식 격차'가 발생하여 최신 개발 사항에 대한 질문에 그럴듯하지만 부정확한 답변을 생성하는 것입니다.

### 특정 도메인 지식의 깊이 부족

파운데이션 모델은 광범위한 지식을 가지고 있지만, 특정 전문 분야에서는 깊이가 부족할 수 있습니다. 이는 해당 도메인의 데이터셋이 비공개여서가 아니라, 매우 특화되어 있기 때문입니다. 예를 들어, 해부학, 질병, 수술 기법에 대해 아는 의료 모델도 희귀 유전 질환이나 최첨단 치료법에 대해서는 어려움을 겪을 수 있습니다.

이러한 한계는 불완전하거나 관련 없는 응답을 초래할 수 있습니다.

### 데이터의 부재

범용 공개 모델의 경우, 사용자의 데이터(예: 기업의 내부 프로세스, 인사 데이터, 이메일 통신, 영업 비밀 등)는 공개되지 않았기에 학습할 수 없습니다(만약 이 데이터가 학습에 포함되었다면, 모델을 사용하는 누구나 해당 기업의 비공개 및 독점 데이터에 접근할 수 있게 될 것입니다.).

이러한 한계 역시 불완전하거나 관련 없는 응답으로 이어져, 특정 비즈니스 목적에 맞는 모델의 유용성을 제한합니다.

### 신뢰도 하락

모델은 일반적으로 특정 응답에 대한 출처를 제시하지 못합니다. 인용이나 참조 없이는 사용자가 응답을 신뢰하거나 직접 사실을 확인해야 합니다. 모델이 방대한 양의 공개 데이터로 학습되었기 때문에, 생성된 응답이 신뢰할 수 없는 출처에서 비롯되었을 가능성이 있습니다. 부정확하고 관련 없으며 쓸모없는 정보가 생성될 때, 사용자는 모델 자체에 대한 신뢰를 잃게 됩니다.

### 확률적 결과 생성

모델은 모든 가능한 다음 단어에 확률을 할당하며, 여기에는 잘못된 단어도 포함됩니다. 따라서 temperature와 top k 같은 샘플링 무작위성과 사용자의 잘못된 프롬프트(지나치게 모호하거나 오해의 소지가 있는 프롬프트 등)가 결합되면 모델이 잘못된 경로를 선택할 수 있습니다.

## 검색 증강 생성(RAG)이란 무엇인가?

검색 증강 생성(Retrieval Augmented Generation, RAG)은 신뢰할 수 있는 외부 데이터를 사용하여 모델 출력의 정확성, 관련성, 유용성을 향상시키는 기술입니다. 이는 다음 네 가지 핵심 구성 요소를 통해 작동합니다.

  1. **수집 (Ingestion)**: 기업의 독점 데이터와 같은 신뢰할 수 있는 데이터를 FAISS나 Pinecone과 같은 벡터 데이터베이스에 로드합니다.
  2. **검색 (Retrieval)**: 사용자 쿼리를 기반으로 외부 데이터 소스에서 관련 데이터를 검색합니다.
  3. **보강 (Augmentation)**: 검색된 데이터와 사용자 쿼리를 결합하여 모델에 컨텍스트를 제공하는 프롬프트를 만듭니다.
  4. **생성 (Generation)**: 모델이 보강된 프롬프트를 기반으로 더 정확하고 관련성 높은 응답을 생성합니다.

### RAG의 이점

  * 실시간 데이터 및 도메인 특화 데이터 접근
    * 사용자의 컨텍스트를 더 잘 파악할 수 있음
  * 신뢰도 증가
    * 더 관련성 있고, 정확한 결과로 신뢰도 증가
    * 출처 인용을 통해 인간이 검토 가능
  * 더 많은 제어권
    * 사용 소스 지정
    * 실시간 데이터 접근
    * 안전 가이드라인(Safety Guideline) 등
  * 타 방식(자체 모델 재학습, 파인튜닝 등) 대비 비용 효율적

### RAG와 AI Agent

벡터 데이터베이스를 사용하고, 증강된 one-shot prompt를 사용하는 이런 전통적인 RAG 접근법은 단순하지만, AI Agent는 RAG의 핵심 구성 요소들을 조율해 다음의 내용을 수행할 수 있습니다. 

* 더 효과적인 쿼리 구성
* 추가 검색 도구 사용
* 검색된 컨텍스트의 정확성과 관련성 평가
* 추론을 통해 정보 검증

## RAG의 작동 방식

RAG는 네 가지 주요 구성 요소로 구현됩니다.

### 데이터 수집 (Ingestion)

사용자의 데이터를 데이터베이스에 입력하기 위해 다음 단계를 거칩니다.

1.  **데이터 청킹 (Chunk the data)**: 텍스트, PDF, 이메일 등 구조화되거나 비구조화된 데이터를 정리한 후, 각 문서를 더 작은 조각(청크)으로 나눕니다.
2.  **벡터 임베딩 생성 (Create vector embeddings)**: 임베딩 모델을 사용하여 각 청크를 데이터의 의미를 나타내는 숫자 표현인 벡터 임베딩으로 변환합니다.
3.  **벡터 데이터베이스에 로드 (Load data into a vector database)**: 생성된 벡터를 벡터 데이터베이스에 로드합니다.

### 검색 (Retrieval)

사용자 쿼리로부터 벡터 임베딩을 생성하여 데이터베이스의 벡터들과 비교해 검색합니다. 의미 기반 검색(Semantic Search)만 사용하는 것이 가장 간단한 방법이지만, 키워드 기반 검색(Lexical Search)을 결합한 하이브리드 검색을 사용하면 검색 결과를 더욱 향상시킬 수 있습니다. 사용자 쿼리가 도메인 특화 적일수록 하이브리드 검색이 더욱 유의미합니다.

하이브리드 검색을 통해 검색된 결과는 관련성 점수를 기반으로 순위가 다시 매겨져 가장 관련성이 높은 결과가 반환됩니다.

### 보강 (Augmentation)

검색 단계에서 얻은 가장 관련성 높은 결과와 사용자의 원래 질문을 결합하여 LLM에 전달할 보강된 프롬프트를 생성합니다. 보강된 프롬프트는 다음과 같은 형태를 가질 수 있습니다.

```
QUESTION:
<사용자의 질문>

CONTEXT:
<검색 결과>

제공된 CONTEXT를 사용하여 QUESTION에 답변하세요. 답변은 CONTEXT의 사실에 근거해야 합니다. 만약 CONTEXT에 답변이 없다면, 모른다고 답하세요.
```

### 생성 (Generation)

보강된 프롬프트를 받은 LLM은 벡터 데이터베이스에서 제공된 가장 적절하고 근거 있는 사실에 접근하여 사용자에게 정확한 답변을 제공하고 환각의 가능성을 줄입니다.

에이전트 기반 RAG에서는 LLM 자체가 어떻게 쿼리할지, 어떤 검색 도구를 사용할지, 언제 검색 도구를 사용하고 검색 결과를 합칠지 등을 결정합니다.

## 마무리

검색 증강 생성(RAG)은 단순한 유행어에서 AI 애플리케이션의 필수적인 기반으로 발전했습니다. 이는 파운데이션 모델의 광범위한 능력과 기업의 신뢰할 수 있는 독점적 지식을 결합합니다.

AI 에이전트가 더 복잡한 사용 사례를 처리함에 따라 RAG는 2025년에도 여전히 중요할 뿐만 아니라, 더 정확하고 관련성 있으며 책임감 있는 AI 애플리케이션을 구축하는 데 필수적입니다. AI 에이전트가 더 자율적으로 작동하고 복잡한 워크플로우를 처리하게 되면서, RAG를 통해 프라이빗 데이터 및 도메인 특화 데이터에 추론의 근거를 두게 될 것입니다.

따라서 이제 RAG를 구현할지를 고민하는게 아니라, 우리의 구체적인 상황과 데이터 요구사항에 맞게 효과적으로 설계하는 방법을 고민해야 합니다.
