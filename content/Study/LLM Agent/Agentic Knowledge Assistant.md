## 개요
사용자가 단순 질문부터 복잡한 리서치 작업까지 다양한 형태의 입력을 제공하면, 시스템이 짧은 답변부터 구조화된 보고서에 이르기까지 맞춤형 결과물을 생성하는 지식 어시스턴트 구축이 목표이다. 이는 단순한 질의응답(Q&A)을 넘어, 복잡한 의사결정을 지원하고 리서치 과정을 자동화하는 수준까지 확장하는 것을 의미한다. 이 문서는 기존 RAG(Retrieval-Augmented Generation)의 한계를 살펴보고, 이를 극복하기 위한 멀티모달 데이터 처리, 에이전트적 추론, 프로덕션 배포 등 고도화된 지식 어시스턴트의 핵심 아이디어를 정리한다.

## 기존 RAG의 한계
기본적인(Naive) RAG 파이프라인은 간단한 질문에는 효과적일 수 있으나, 복잡한 작업을 처리하는 데에는 명확한 한계를 보인다. 이러한 한계는 주로 데이터 처리, LLM 활용 방식, 그리고 시스템의 구조적 제약에서 비롯된다.

### 원시적인 데이터 처리
기존 RAG는 문서 파싱 시 표, 이미지, 또는 복잡한 시각적 레이아웃 같은 비정형 요소를 제대로 처리하지 못한다. 표준 파서는 텍스트를 단순히 일정한 크기로 분할하여 의미적으로 중요한 컨텍스트를 파괴할 수 있다. 결국 "Garbage in, garbage out" 원칙에 따라, 부정확하게 처리된 데이터는 LLM의 환각(Hallucination)을 유발하고 답변의 신뢰도를 떨어뜨린다.

### 제한적인 LLM 활용
대부분의 기본 RAG 파이프라인은 LLM을 검색된 정보를 단순히 요약하고 종합하는 역할(synthesis)에만 국한하여 사용한다. 이는 최신 LLM이 가진 다단계 추론(multi-step reasoning), 계획(planning), 도구 사용(tool use)과 같은 고도의 에이전트적 능력을 제대로 활용하지 못하는 것이다.

### 상태 비저장(Stateless) 파이프라인
기존 RAG 시스템은 일반적으로 상태를 저장하지 않는(stateless) 일회성(one-shot) 구조를 가진다. 이는 사용자의 이전 질문이나 대화의 맥락을 기억하지 못하므로, 개인화된 경험을 제공하거나 연속적인 작업을 수행하는 데 한계가 있다.

## 고도화된 지식 어시스턴트의 핵심 아이디어
기존 RAG의 한계를 극복하고 더 일반화된 지식 어시스턴트를 구축하기 위해서는 멀티모달 데이터 처리, 에이전트적 추론, 그리고 확장 가능한 아키텍처 설계가 필수적이다.

### 고품질 멀티모달 RAG
복잡한 문서를 정확히 이해하기 위해서는 텍스트뿐만 아니라 표, 이미지 등 시각적 데이터를 통합적으로 처리하는 멀티모달 RAG가 필요하다. 이를 위해선 우선 LlamaParse와 같이 복잡한 문서 구조를 정확하게 파싱하여 데이터 무결성을 유지하는 기술이 중요하다. 이후 텍스트, 표, 이미지 등 분할된 요소들을 각각 인덱싱한다. 검색 시에는 텍스트와 이미지를 모두 활용하여 멀티모달 LLM에 전달함으로써, 모델이 시각적 데이터를 포함한 질문에도 더 정확한 답변을 생성하도록 유도할 수 있다.

#### 이상적인 Parser의 특성
- 필수 요건
    - 표를 텍스트와 준구조화(semi-structured representation)된 형태로 정확하게 변환.
    - 텍스트를 의미적으로 일관된 청크(chunk)로 분할.
    - 이미지, 도표 등 시각적 요소를 구조화된 형식으로 추출하고 이미지 청크로 반환.
    - 자동화된 메타데이터 추출.
- 비필수 요건
    - 모든 요소를 상세한 JSON 형태로 추출.
    - 경계 박스(bounding box)를 추출.

### 에이전트적 추론 (Agentic Reasoning)
에이전트적 추론은 LLM이 복잡한 문제에 대해 계획을 세우고, 여러 단계를 거쳐 해결하도록 만드는 접근 방식이다. 이는 RAG를 단순한 정보 검색 도구로 취급하고, 그 위에 에이전트 계층을 두어 쿼리를 분해하고 적절한 도구를 호출하게 만드는 'Agentic RAG' 개념으로 확장된다. 에이전트의 제어 흐름은 크게 두 가지로 나눌 수 있다.
- **제약적 흐름 (Constrained Flow)**: 개발자가 if-else 문처럼 명확한 제어 흐름을 직접 설계하는 방식이다. 이는 에이전트의 행동을 예측 가능하게 만들어 신뢰성은 높지만, 유연성과 표현력은 제한된다.
- **비제약적 흐름 (Unconstrained Flow)**: 에이전트에게 여러 도구를 제공하고, 스스로 계획을 세워 작업을 해결하도록 맡기는 Agent Orchstration 방식이다 (예: ReAct). 다양한 작업을 해결할 수 있는 표현력은 높지만, 에이전트가 잘못된 경로로 빠지거나 무한 루프에 갇히는 등 신뢰성이 낮고 비용이 더 많이 발생할 수 있다.

#### Agent Orchestration의 핵심
- **이벤트 기반(Event-Driven)**: 각 단계를 입력 이벤트를 수신하고 출력 이벤트를 생성하는 방식으로 모델링.
- **구성 가능(Composable)**: 세분화된 워크플로를 결합하여 상위 수준의 워크플로로 구성.
- **유연성(Flexible)**: LLM 호출 또는 순수 파이썬으로 로직 작성.
- **코드 우선(Code-first)**: 오케스트레이션 로직을 코드로 표현. 읽기 쉽고 확장하기 용이함.
- **디버그 및 관찰 가능(Debuggable and Observable)**: 단계별 상태를 확인하고 관찰 가능.
- **프로덕션 배포 용이(Easily Deployable to Production)**: 노트북 코드를 프로덕션 환경에서 실행 가능한 서비스로 변환.

### 복잡한 결과물 생성
고도화된 에이전트는 단순한 챗봇 응답을 넘어, 사용자가 실제 업무에 바로 사용할 수 있는 지식 결과물(knowledge work)을 생성해야 한다. 예를 들어, 여러 문서를 바탕으로 한 `리서치 보고서`, 데이터 분석이 포함된 `슬라이드 덱`, 또는 실행 가능한 `코드`를 생성하는 것이 여기에 해당한다. 이는 시간 절약과 업무 능력 향상 측면에서 훨씬 큰 투자수익률(ROI)을 가져올 수 있다.

### 프로덕션 아키텍처
복잡한 에이전트 워크플로우를 안정적으로 운영하기 위해서는 확장 가능한 프로덕션 아키텍처가 필수적이다. 각 에이전트 워크플로우를 독립된 마이크로서비스로 캡슐화하고, 중앙 메시지 큐(central message queue)를 통해 에이전트 간의 통신을 표준화하는 방식이 제안된다. 또한, 에이전트가 스스로 해결할 수 없는 문제에 부딪혔을 때 사용자에게 입력을 요청하고 응답을 기다리는 '인간의 개입(human-in-the-loop)' 기능을 통합하여 상호작용의 완성도를 높일 수 있다.
